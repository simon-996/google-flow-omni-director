# 项目目录、命名与备份

## 保存位置

项目文件放在独立的项目目录，遵循用户指定的路径。Windows 可访问本地文件时，默认以 `D:\workplace\omni-flow-projects\` 为项目集合目录。新目录名用 `YYYY-MM-DD_片名`。日期按用户时区，片名沿用用户给出的名字，移除 Windows 不允许的字符。已有项目续用已确认的目录，同日同名的新项目加 `_02`、`_03` 避免混用。用实际可写的位置完成交付。云端环境可交付同结构的目录或压缩包，告诉用户下载后放到哪里。

~~~text
YYYY-MM-DD_片名/
├── 00_项目制作总指南.md
├── 01_剧本与故事结构.md
├── 02_人物资产制作清单.md
├── 03_场景与道具制作清单.md
├── 04_完整分镜脚本.md
├── 05_Flow逐镜提示词与素材引用.md
├── 06_制作顺序与依赖关系.md
├── 07_质量检查与返工指南.md
├── asset-manifest.xlsx
├── backup/
├── inputs/
├── assets/
│   ├── characters/
│   ├── scenes/
│   ├── props/
│   └── shot-references/
├── flow-renders/
│   └── SHOT-001/
├── post/
└── exports/
~~~

每个创建或使用的项目内容目录都建一个直接子目录 `backup/`。这包含根目录、`assets/`、人物/场景/道具/镜头参考的各目录、每个镜头的回片目录和各级后期内容目录。`backup/` 自身到此为止。上图只显式展示了根目录的备份位置。所有视频提示词集中在根目录 `05_Flow逐镜提示词与素材引用.md`。

## 文件与资产编号

| 内容 | 位置 | 示例 |
|---|---|---|
| 用户原始文件 | `inputs/` | 原文件名。若同名但内容不同，先确认所属，按需要使用独立子目录保留原名 |
| 人物图 | `assets/characters/` | `CHAR-001-sheet-V01.png`。可使用 `front`、`side`、`back`、`face` 等用途 |
| 场景图 | `assets/scenes/` | `SCENE-001-main-V01.png` |
| 道具图 | `assets/props/` | `PROP-001-ref-V01.png` |
| 镜头参考图 | `assets/shot-references/` | `SHOT-003-start-V01.png`，尾帧使用 `end` |
| 单镜提示词编号 | 提示词总表内 | `SHOT-003-PROMPT-V02` |
| Flow 回片 | `flow-renders/SHOT-003/` | `SHOT-003-PROMPT-V02-TAKE-01.mp4` |
| 配音、配乐、字幕文件与剪辑工程 | `post/` | `SHOT-003-voice-V01.wav`、`雨夜便利店_BGM_V01.wav`、`雨夜便利店_剪辑_V01.drp` |
| 导出成片 | `exports/` | `雨夜便利店_V01.mp4` |

编号按项目分配，补零至三位，删除镜头后避免复用其编号。新增镜头领新编号，用分镜与提示词中的时间码表示播放顺序。同镜头、同提示词版本下，每条结果增加 TAKE。正式回片保留实际扩展名。若试拍用独立提示词，记录在同一 Markdown 里的「样片」小节，用独立的 `SHOT-003-TEST-01-PROMPT-V01` 编号，避免与正式 TAKE 混用。

## 更新、归档与追溯

1. 先读当前文件、已有归档与资产登记。确认要改的对象和受影响的镜头。内容没有变化时保留原文件和版本。
2. 固定名文档和工作簿先另存本次候选，确认能读取。把当前版归档到同目录的 `backup/`，随后保存新版到固定文件名。例 `backup/05_Flow逐镜提示词与素材引用_V01.md` 和 `backup/asset-manifest_V01.xlsx`。第一次归档从 V01 起，后续在已存在的最大版本上递增。文档原来显式标了版本时，以该已知版本为准并核查冲突。
3. 素材、回片和成片用带版本或 TAKE 的文件名。候选和多个并列 TAKE 可以共存。用户确认新文件替换旧文件后，旧文件才移入其原目录的 `backup/`，归档沿用原文件名。更新登记表时为替换前后的文件保留各自行，写明替换关系和路径。允许历史 TAKE 保留其对应的历史资产版本。若旧归档已有不同内容，保全两份并记录实际归档名。
4. 先验证旧版已经安全归档，再替换或移走原件。操作完核对新版和备份都存在、可读且路径对应。目标文件被占用或写入失败时保留有效原件，说明实际保存状态。禁止覆盖同名且内容不同的备份。
5. 提示词总表只更新受影响镜头的块和相关索引，整份旧文档只归档一次。镜头标题版本和整份文档归档版本独立。在登记表按「镜头 ID＋提示词版本」保留独立记录，写明总表快照的位置、实际绑定的资产 ID、用途和版本。总表归档后保持其内容原样，用登记表或资产 ID 查找已移动的旧资产。
6. 同版素材只从原目录移到 `backup/` 时，同步修正现用总表中的路径和资产表的路径字段，沿用原提示词版本。其他镜头继续使用锁定的旧资产版本，除非用户确认切换素材。切换具体资产版本或改变生成设置时，给受影响镜头升提示词版本，即使可复制代码块的文字相同。
7. 回片按实际使用的设置登记。如果回片上传的素材或 Flow 设置与计划不同，在 TAKE 行记录实际素材 ID、用途和版本、实际设置以及差异。未得到实际操作信息时标待核对。

资产状态可用「待补充、待制作、待审核、已确认、已替换、已废弃」。待制作使用 `[待制作：CHAR-001]` 并留空文件路径。已收到但没经确认的文件保持「待审核」，可作为明确标注的试拍素材。相对路径从项目根目录起，核对之后以实际路径交付。只有项目文件真实写入后，才报告保存或归档完成。
